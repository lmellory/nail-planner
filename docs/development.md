# Разработка и публикация

[← NailBook](../README.md)

## Требования

Node.js `^22.12.0 || ^24.0.0 || >=26.0.0`, npm и зависимости из `package-lock.json`. Для рабочего приложения нужны бот Telegram, Cloudflare Workers и база Turso.

```bash
npm ci
```

## Конфигурация

Скопируйте `.dev.vars.example` в `.dev.vars` и заполните значения локально. В PowerShell: `Copy-Item .dev.vars.example .dev.vars`.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен бота Telegram. |
| `ALLOWED_IDS` | ID мастеров через запятую; доступ также можно выдавать командой `/adduser`. |
| `WEBHOOK_SECRET` | Секрет для проверки запросов Telegram к `/webhook`. |
| `TURSO_URL` | Адрес базы `libsql://…` или `https://…`. Это точное имя переменной, используемое кодом. |
| `TURSO_AUTH_TOKEN` | Токен доступа к Turso. |
| `ADMIN_ID` | ID администраторов через запятую. |
| `VIEWER_IDS` | ID наблюдателей через запятую; может быть пустым. |
| `TZ` | Часовой пояс по умолчанию, например `Europe/Chisinau`. |
| `APP_URL` | HTTPS-адрес опубликованного Mini App для кнопок бота. |
| `ENABLE_ID_COMMAND` | Включение команды `/id`. |

Несекретные настройки находятся в `wrangler.toml`, локальные секреты — в `.dev.vars`. Для собственной установки замените имя Worker, адрес базы, URL приложения и ID из конфигурации репозитория на свои. `.dev.vars` не коммитится.

Для разработки используйте отдельные тестовые базу и бота. `npm run dev` подключается к базе из локальной конфигурации; само слово «локально» не делает удалённую базу тестовой.

## Миграции и локальный запуск

Заполните `TURSO_URL` и `TURSO_AUTH_TOKEN` в `.dev.vars`, затем выполните:

```bash
npm run migrate
npm run dev
```

Мигратор читает подключение из `.dev.vars`, отслеживает версии в `schema_migrations` и применяет только недостающие файлы из `migrations/`. Каждая миграция и отметка о её применении выполняются одной транзакцией. `MIGRATE_DB_URL`, `MIGRATE_DB_TOKEN`, `MIGRATIONS_DIR` переопределяют подключение и каталог для тестов.

API требует подписанный Telegram `initData`. Обычная вкладка браузера без Telegram не авторизует пользователя. Для проверки настоящего входа открывайте Mini App из тестового бота по доступному HTTPS-адресу; браузерные тесты используют подмену Telegram и API.

## Проверки

| Команда | Что проверяет |
| --- | --- |
| `npm run typecheck` | TypeScript сервера, все JS-модули интерфейса в режиме `checkJs` + `strict`, контракты API. |
| `npm test` | Расчёты, подпись Telegram, доступ, миграции, обработчики, транзакции и экраны в jsdom. |
| `npm run test:browser` | Chromium и WebKit: размеры полей, прокрутка, формы, ошибки и предупреждения. |
| `npm run test:load` | Сценарии параллельной работы с искусственными данными. |
| `npm audit --audit-level=high` | Уязвимости зависимостей. |
| `npm run version-assets` | Версия JS/CSS в HTML по содержимому файлов и их зависимостей. |

Для одного файла: `npm test -- test/ui.test.ts`.

Перед первым браузерным запуском:

```bash
npx playwright install chromium webkit
npm run test:browser
```

На Linux с системными зависимостями: `npx playwright install --with-deps chromium webkit`. Для установленного Chrome задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE` с полным путём к исполняемому файлу; WebKit устанавливается отдельно.

В Playwright шесть конфигураций: Android, iPhone, узкий и горизонтальный экраны, настольные Chromium и WebKit. Это эмуляция браузеров и размеров, а не проверка физических телефонов и клавиатуры Telegram. Внешняя сеть блокируется, API и Telegram подменяются.

Интеграционные тесты создают временную SQLite с настоящими миграциями; `.dev.vars` и рабочая база не нужны. `scripts/test.js` удаляет тестовые базы после завершения дочернего процесса, освобождая удерживаемые libSQL файлы на Windows.

Нагрузочный сценарий использует 10 искусственных мастеров и 10 000 записей: 100 одновременных чтений, 20 сохранений и попытки удаления чужих записей. Он проверяет изоляцию и сохранность прежних строк на локальной SQLite. Его время ответа не определяет пропускную способность Cloudflare/Turso. Эти сценарии входят и в обычный `npm test`.

## Публикация

Войдите в Cloudflare через `npx wrangler login`, проверьте конфигурацию нужного Worker и задайте секреты:

```bash
npx wrangler secret put BOT_TOKEN
npx wrangler secret put ALLOWED_IDS
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put TURSO_AUTH_TOKEN
```

`TURSO_URL`, `TZ`, `APP_URL`, `ADMIN_ID` и остальные несекретные параметры задаются в `[vars]` файла `wrangler.toml`. `.dev.vars` не заменяет настройку секретов опубликованного Worker.

Для существующей базы перед миграциями сохраните копию и проверьте выбранное подключение. Затем:

```bash
npm run typecheck
npm test
npm run deploy
```

`deploy` обновляет версии статики и публикует Worker с интерфейсом. Миграции автоматически не запускаются: `npm run migrate` выполняется отдельно, когда в выпуске есть новые SQL-файлы.

После первого деплоя впишите полученный HTTPS-адрес в `APP_URL` и опубликуйте конфигурацию повторно. Установите webhook, подставив свои значения локально:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<WORKER_HOST>/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

Пример использует синтаксис Bash; на Windows можно выполнить его в Git Bash. Секрет должен совпадать с `WEBHOOK_SECRET` Worker. Откройте чат тестового бота, отправьте `/start` и воспользуйтесь кнопкой входа в приложение.

В CI запускаются установка зависимостей, audit, версия статики, типы, SQLite/jsdom и браузерные тесты. При ошибке браузера скриншоты, трассировки и HTML-отчёт сохраняются на 7 дней.
