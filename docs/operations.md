## Резервные копии

В приложении откройте **Настройки → Резервная копия сейчас**. Бот пришлёт JSON-файл в личный чат. Он содержит записи, клиентов, траты, прайс, заметки и настройки одного мастера. Сохраните файл отдельно от переписки.

При включённой еженедельной копии бот отправляет её за воскресный слот 21:00 в часовом поясе мастера. Если слот был пропущен, копия досылается; при первом включении копия отправляется сразу. Для получения файлов мастер должен начать диалог с ботом и не блокировать его.

| Команда администратора | Результат |
| --- | --- |
| `/export ID` | CSV и полная JSON-копия данных указанного мастера. |
| `/backupall` | Отдельные JSON-копии пользователей из базы. |
| `/records` | CSV со всеми записями и ID владельцев. |

CSV удобен для просмотра в Excel. Для восстановления через приложение нужен JSON. Пользовательская JSON-копия не является полным дампом схемы, прав доступа и всех служебных таблиц базы.

## Восстановить данные одного мастера

1. Сохраните отдельную копию его текущих данных.
2. Откройте Mini App под нужным аккаунтом Telegram. В режиме администратора «за мастера» импорт закрыт.
3. В **Настройках** нажмите **«Восстановить из копии (JSON)»** и выберите файл.
4. Проверьте отчёт: количество записей, клиентов, трат и заметок, число пропущенных повреждённых строк.
5. Подтвердите восстановление, затем проверьте расписание и данные клиента.

Предварительная проверка файла ничего не меняет. Подтверждение **заменяет текущие данные этого мастера** содержимым копии, включая настройки и прайс. Операция выполняется одной транзакцией; ошибка внутри неё откатывает изменения. Совместимость со старыми копиями без поля `format` сохранена.

## Диагностика

Начните с `/health` в чате администратора. Команда проверяет базу и миграции, доступность бота, состояние webhook, очередь и последнюю ошибку доставки. `/user ID` показывает состояние конкретного пользователя; `/stats` — сводку по базе.

Логи доступны в панели Cloudflare и в терминале:

```bash
npx wrangler tail
```

В `wrangler.toml` включена observability. Для изменений записей в режиме «за мастера» журнал содержит `admin-act`, ID администратора и владельца, метод, путь и HTTP-статус. Токены и содержимое резервных копий не публикуйте в issues и снимках экрана.

| Симптом | Что проверить |
| --- | --- |
| Приложение просит войти заново | Откройте Mini App из бота повторно: подписанная сессия действует до 24 часов. |
| Нет доступа | Аккаунт Telegram, `ALLOWED_IDS`, выдачу через `/adduser`, наличие блокировки `/ban`. |
| Расписание пустое | Выбранную дату, аккаунт и плашку режима администратора. Отменённые записи и неявки не занимают свободные окна. |
| Не сохраняется форма | Соединение и сообщение об ошибке. При потере ответа проверьте результат сохранения перед повтором, чтобы не создать лишнюю запись. |
| Не приходят сообщения | Диалог с ботом, настройки уведомлений, часовой пояс, webhook и Cron через `/health` и логи. |
| После публикации старый интерфейс | Перезапустите Mini App; проверьте успешный деплой и версию JS/CSS в `index.html`. |

## Обновление приложения

Перед изменением схемы или массовыми операциями с данными сохраните резервную копию нужного охвата. Для изменения всех пользователей нужны копии всех мастеров; для работы со служебными таблицами — отдельная копия базы и схемы.

Обычный выпуск:

1. Проверьте изменения, типы и тесты; дождитесь CI.
2. Если добавлены SQL-миграции, проверьте их на тестовой базе и выбранное подключение перед `npm run migrate`.
3. Выполните `npm run deploy` и сохраните ID опубликованной версии из вывода Wrangler.
4. Проверьте вход, расписание, создание и редактирование тестовой записи на своём аккаунте.
5. После изменения базы сверяйте владельцев, количество и содержимое прежних записей.

Документация и картинки из `docs/` публикуются на GitHub. Их изменение само по себе не требует деплоя Worker или миграции.

## Вернуть предыдущую версию приложения

Выберите ID ранее работавшей версии в истории развёртываний Cloudflare. Для возврата кода:

```bash
npx wrangler rollback <VERSION_ID>
```

Команда возвращает версию Worker, а данные Turso и применённые SQL-миграции остаются текущими. Перед возвратом убедитесь, что выбранная версия совместима со схемой. Восстановление пользовательских данных из JSON — отдельная операция, описанная выше.

## Разделение данных

Записи принадлежат `user_id`. Удаление записей одного мастера ограничивается его ID; имени клиента или общих признаков тестовых данных недостаточно. Перед массовой очисткой уточняются владелец и перечень таблиц, после — сверяются данные остальных мастеров.

Удаление записи через приложение не удаляет карточку клиента. Блокировка пользователя закрывает доступ и сохраняет его данные. Изменение подписи валюты в `webapp/js/money.js` меняет отображение, а не суммы и не выполняет пересчёт.
