## Карта проекта

```text
src/
  index.ts          Worker: API, webhook, Cron
  auth.ts           Проверка Telegram и прав доступа
  api/              HTTP-маршруты
  bot/              Команды и обращения к Telegram
  db/               Запросы к данным по областям
  lib/              Расчёты, валидация, резервные копии, адаптер Turso
  cron.ts           Напоминания, дни рождения, копии, удаление сообщений
migrations/         Версии SQL-схемы
webapp/
  index.html        Разметка экранов
  app.js            Инициализация интерфейса
  js/               Нативные ES modules
  style.css         Порядок CSS-импортов
  css/              Стили экранов и общих элементов
scripts/            Миграции, проверки, версия статики, тестовый сервер
test/               Логика, SQLite, jsdom, контракты типов
  browser/          Playwright и демонстрационные данные
docs/               Документация и снимки интерфейса
```

## Путь запроса

Mini App отправляет `X-Init-Data`. Сервер проверяет подпись Telegram и доступ пользователя, определяет владельца данных, валидирует запрос и обращается к репозиторию в `src/db/`. Клиент не выбирает владельца произвольным полем в теле запроса.

Администратор может работать с записями мастера через `X-Act-As`. Этот режим проверяется сервером, ограничивается разрешёнными маршрутами и записывает изменения в логи. Смена мастера сбрасывает зависимые данные интерфейса; старые ответы отсекаются по версии контекста.

## Модули интерфейса

Все пути в таблице относятся к `webapp/js/`.

| Модули | Ответственность |
| --- | --- |
| `api.js`, `api-contracts.js`, `contracts.d.ts` | HTTP, ошибки, типизированные ответы и запросы API. |
| `state.js`, `dates.js`, `money.js`, `labels.js` | Общее состояние и преобразования. |
| `telegram.js`, `telegram-sdk.d.ts`, `ui.js` | Telegram SDK, подтверждения, уведомления. |
| `navigation.js`, `navigation-events.js` | Переключение экранов и события навигации. |
| `requests.js`, `drafts.js` | Актуальность запросов, одно сохранение за раз, защита несохранённых форм. |
| `schedule.js`, `appointment-form.js`, `calendar-search.js` | Неделя, карточки, форма, календарь и поиск. |
| `clients.js`, `admin.js` | Клиенты и работа администратора. |
| `notes.js`, `settings.js`, `prices.js`, `backup.js` | Заметки, настройки, прайс, экспорт и восстановление. |
| `income.js`, `expenses.js`, `finance-state.js` | Отчёты, траты и выбранный период. |
| `dom.js` | Типизированный доступ к DOM. |

HTML подключает один `app.js`; зависимости задаются через `import`, сборщик не нужен. Все модули интерфейса проходят строгую проверку типов.

## Данные и транзакции

Основные таблицы: `appointments`, `clients`, `expenses`, `day_notes`, `service_prices`, `users`. Доступ хранится в `access`, очередь удаления сообщений — в `scheduled_deletes`, история миграций — в `schema_migrations`.

Создание записи вместе с клиентом, переименование клиента вместе с историей, сохранение прайса и восстановление копии выполняются транзакционно. Переименование клиента сохраняет ID записей и ограничивается владельцем.

Услуги и статусы проверяются в `src/lib/services.ts` и `src/lib/status.ts`. Длительность по умолчанию задаётся в `src/lib/time.ts`: маникюр — 120 минут, педикюр — 90, обе услуги — 210, маникюр с обработкой пальцев — 180. Старая услуга `fingers` поддерживается для прежних данных.

## Формы и стили

`drafts.js` сравнивает значения с последними загруженными или успешно сохранёнными. Настройки и прайс отслеживаются отдельно. Возврат исходных значений снимает предупреждение. Черновики не записываются в браузерное хранилище; при принудительном завершении приложения восстановление несохранённой формы не предусмотрено.

`requests.js` блокирует повторное сохранение и поля формы на время операции. При ошибке значения остаются доступными для исправления и повторной попытки.

`style.css` сохраняет порядок импортов из `webapp/css/`: он важен для каскада. `npm run version-assets` обходит JS- и CSS-зависимости и обновляет версию в HTML. Правила кеширования находятся в `webapp/_headers`.
