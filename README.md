# 💅 Ежедневник мастера маникюра: Telegram Mini App

Telegram Mini App + бот-ассистент для мастера маникюра и педикюра.  
Работает 24/7 в бессерверном облаке **Cloudflare Workers** с базой данных **Turso (libSQL/SQLite)**.

---

## 🌸 Возможности

- **📅 Полоса недели со свайпом (Пн–Вс)**: индикация записей точками и значок 📝 при наличии заметок.
- **✨ Свободные окна дня**: автоматический расчёт и визуальные бейджи свободных окон с учётом графика работы мастера и существующих записей; клик по окну сразу открывает форму записи на это время.
- **💅 Запись клиентов**:
  - Быстрый выбор времени начала приёма.
  - Опциональная длительность (по умолчанию: маникюр 2 ч, педикюр 1.5 ч, «оба» 3.5 ч, «маникюр + пальцы» 3 ч) с возможностью изменить в один клик.
  - Услуги: маникюр / педикюр / оба / маникюр + пальцы. У «маникюр + пальцы» покрытие не выбирается. Старая отдельная услуга «пальцы» в форме больше не предлагается, но прежние записи с ней открываются и считаются в доходах как раньше.
  - Цена записи (необязательная, целое число). Раздел «Доходы» в нижнем меню: диаграмма и итоги за неделю, месяц и год, средний чек, сравнение с прошлым периодом. Валюта задаётся константой `CURRENCY` в `webapp/js/money.js`.
  - Траты на материалы: каждая покупка — отдельная запись (дата, название, сумма). На экране «Доходы» переключатель «Доход / Траты», прибыль за период и разбивка «Траты по материалам»; кнопка «Все траты за период» открывает список с правкой и удалением. Траты попадают и в JSON-бэкап.
  - Прайс услуг (Настройки → «Прайс услуг»): цена подставляется в новую запись и при смене услуги; вручную введённую цену не затирает.
  - Еженедельная резервная копия: по воскресеньям в 21:00 бот присылает JSON (записи, клиенты, траты, прайс, заметки, настройки). Включается в Настройках; пропущенная неделя досылается, повторов нет. Кнопка «Резервная копия сейчас» там же.
  - CSV «Доходы и траты» за выбранный период (кнопка на экране «Доходы»): доходы и траты построчно, итоги, прибыль и траты по материалам.
  - Статус записи: запланирована / не пришла / отменена. «Не пришла» и «Отменена» освобождают время (не дают конфликтов, не считаются в окнах, календаре и расписании бота) и не входят в доход. Доход считает только состоявшиеся записи (время начала уже прошло), будущие показываются как «Ожидается»; сорванные записи — отдельной строкой.
  - Восстановление из резервной копии (Настройки → «Восстановить из копии (JSON)»): сначала проверка файла и отчёт «что будет восстановлено», затем замена всех данных одной транзакцией (при сбое ничего не меняется). Понимает и старые копии без поля `format`.
  - Услуги и статусы проверяются в коде (`src/lib/services.ts`, `src/lib/status.ts`), а не в БД: новая услуга или статус не требует миграции.

  - Раздельные покрытия: с покрытием (гель) / без покрытия.
  - Автоматическая проверка интервальных пересечений $[start, end)$ с понятным предупреждением.
  - Автоподстановка клиентов из базы при вводе имени.
- **👥 База клиентов (отдельный раздел)**:
  - Карточки клиентов с поиском.
  - Номер телефона с быстрым звонком и кликабельная ссылка на профиль Telegram.
  - Индивидуальные заметки мастера (аллергия на материалы, предпочтения, особенности).
  - 🎂 **День рождения клиентки**: указание числа и месяца, праздничный бейдж и **автоматическое напоминание от бота в 10:00 утра** (по Кишиневу) в день рождения клиентки со всеми её контактами.
  - История визитов и кнопка быстрой записи.
- **📝 Заметки на каждый день**: сохраняются в приложении и мгновенно дублируются сообщением в Telegram.
- **🔔 Сообщения о записях и заметках**: бот присылает уведомления при создании и автоматически удаляет их из чата через сутки, чтобы не засорять переписку мастера.
- **🌙 Вечерние напоминания**: бот каждый вечер (по умолчанию в 22:00) присылает расписание на завтра со списком клиентов, контактами (телефон / Telegram) и заметкой.
- **⚙️ Настройки графика**: выбор рабочих дней (Пн–Вс), начала и окончания рабочего дня, времени вечернего уведомления.
- **🔒 Надёжность сессии и защита от гонок**:
  - При истечении срока `initData` (24 часа) отображается понятный экран с кнопкой перезагрузки без ложных ошибок 403.
  - Защита от race conditions на фронтенде при быстром переключении дней (`AbortController` + sequential `requestId`).
- **📊 Экспорт в Excel / CSV**: безопасная выгрузка всех записей в таблицу CSV (с сохранением телефонных номеров с `+` и защитой от CSV-инъекций) прямо в чат Telegram.
- **🎨 Дизайн**: мобильный интерфейс, нежная пудрово-розовая палитра, полная поддержка светлой и тёмной тем Telegram.

## 🛠 Стек технологий

- **Бэкенд**: Cloudflare Workers, TypeScript, Hono.
- **База данных**: Turso (libSQL / SQLite) через `@libsql/client/web` (атомарные транзакции `batch`).
- **Фронтенд**: Чистый JavaScript (Vanilla), HTML5, CSS3 без сборщиков и сторонних фреймворков.
- **Telegram WebApp**: BackButton, MainButton, HapticFeedback, showConfirm.
- **Фоновые задачи**: Cloudflare Cron Triggers (`* * * * *`): проверка вечерних уведомлений и автоудаление сервисных сообщений из чата.
- **Тесты**: Vitest (`npm test`): подпись Telegram, валидация, расчёты, вечерние и недельные уведомления, интеграционные тесты обработчиков и миграций на настоящей SQLite, сквозные тесты экранов (см. раздел «Тесты» ниже).

## Структура проекта

Сервер находится в `src/`: маршруты в `api/`, Telegram-бот в `bot/`, общие функции в `lib/`. Схема базы развивается SQL-миграциями в `migrations/`.

Интерфейс использует нативные ES modules без сборщика: HTML подключает один `webapp/app.js`, а зависимости каждого файла указаны через `import`.

| Модуль | Ответственность |
| --- | --- |
| `webapp/js/api.js` | HTTP, подпись Telegram, ошибки и отсечение ответов предыдущего мастера |
| `state.js`, `dates.js`, `money.js`, `labels.js` | Состояние и общие преобразования |
| `telegram.js`, `ui.js` | Telegram SDK, подтверждения, уведомления |
| `navigation.js`, `navigation-events.js` | Переключение экранов и подключение навигации |
| `requests.js` | Последний актуальный запрос и защита от повторного сохранения |
| `schedule.js`, `appointment-form.js`, `calendar-search.js`, `clients.js`, `admin.js` | Расписание, записи, календарь, клиенты и администрирование |
| `notes.js`, `settings.js`, `prices.js`, `backup.js` | Заметки дня, настройки, прайс, экспорт и восстановление |
| `income.js`, `expenses.js`, `finance-state.js` | Доходы, расходы и общее состояние выбранного периода |
| `api-contracts.js`, `contracts.d.ts`, `dom.js` | Типизированные API настроек/прайса, состояние приложения и доступ к полям форм |

`webapp/style.css` задаёт порядок импортов из `webapp/css/`: базовые правила, расписание, формы, календарь и поиск, настройки, уведомления, клиенты, доходы, расходы, статусы и навигация. Порядок важен для каскада; стили экранов редактируются в соответствующих файлах. Все CSS-зависимости входят в расчёт версии статики.

Серверные запросы разделены на репозитории в `src/db/`: пользователи, администрирование, записи, клиенты, заметки, уведомления, расходы, прайс и отчёты. `src/db.ts` сохраняет совместимые экспорты. Валидация клиентов и представление настроек находятся в `src/lib/`, не зависят от HTTP и используются при импорте. Существующие таблицы и миграции сохранены.

Создание записи вместе с клиентом, переименование клиента вместе с историей, сохранение прайса и восстановление данных вместе с настройками выполняются транзакционно. Переименование сохраняет ID записей и ограничивается одним мастером.

`npm run version-assets` обновляет `?v=` у всех локальных JS/CSS в HTML по содержимому файлов, включая вложенные модули. Команда входит в `npm run deploy` и CI. `webapp/_headers` запрещает хранить HTML и требует перепроверять статику, чтобы после выкладки загружался актуальный набор файлов.

## Тесты

`npm test` запускает расчёты, интеграционные тесты обработчиков и сквозные проверки экранов. Интеграционные и экранные тесты используют настоящую SQLite с боевыми миграциями и настоящий сервер; внешние вызовы Telegram подменяются. Тесты не требуют ни Turso, ни сети.

Экранные тесты исполняют настоящий граф ES modules в jsdom через Node VM modules. Проверяются доходы, расходы, настройки, запись, восстановление, календарь, поиск, заметки, клиенты и работа администратора за мастера.

`scripts/test.js` запускает Vitest в отдельном процессе и удаляет временные базы после его завершения: на Windows нативный libSQL может удерживать файлы до выхода процесса. Ошибки тестов сохраняют ненулевой код завершения. Для запуска одного файла: `npm test -- test/ui.test.ts`.

`npm run typecheck` проверяет сервер и весь интерфейс, включая синтаксис, имена, импорты, DOM и ответы API. Все модули интерфейса проходят строгую проверку типов (`checkJs` + `strict`), включая формы, клиентов, расписание, финансы и Telegram SDK. Исключений для отдельных экранов или кодов ошибок нет. Контракты настроек и записей используют серверные типы; `test/types/frontend.ts` проверяет, что неверные поля и типы отклоняются компилятором. Новые регрессионные тесты проверяют откат транзакций, сохранность ID и изоляцию мастеров, гонки запросов и двойное сохранение.

Браузерные проверки находятся в `test/browser/` и запускают настоящий Chromium и WebKit в шести конфигурациях: Android, iPhone, узкий экран, горизонтальный экран и два настольных браузера. Они проверяют размеры полей, доступность последней карточки над меню, сохранение без дублирования кнопок, настройки, прайс, расходы и клиентов. Дополнительные сценарии проверяют задержку сети, ошибку сохранения с повтором и расписание из 500 карточек. API и Telegram подменяются; внешняя сеть блокируется. Эти тесты не обращаются к рабочей базе.

Первый запуск: `npx playwright install chromium webkit` (Linux: `npx playwright install --with-deps chromium webkit`), затем `npm run test:browser`. При нехватке места для Chromium можно задать переменную `PLAYWRIGHT_CHROMIUM_EXECUTABLE` с путём к установленному Chrome; WebKit всё равно нужен отдельно. CI всегда использует версии браузеров из Playwright.

CI (`.github/workflows/ci.yml`) проверяет подготовку статики, типы, тесты SQLite/jsdom и браузерные проверки на каждый пуш и pull request. При ошибке сохраняются скриншоты, трассировки и HTML-отчёт на 7 дней.

Формы записи, заметки, клиента, траты, настроек и прайса предупреждают о несохранённых изменениях при выходе. Настройки и прайс учитываются отдельно: сохранение одного блока не снимает защиту другого. В Telegram дополнительно включается подтверждение закрытия, в обычном браузере — стандартное предупреждение при перезагрузке или закрытии вкладки, когда браузер его поддерживает. Проверка сравнивает текущие значения с последними загруженными или успешно сохранёнными; возврат исходных значений снимает предупреждение. Черновики не записываются в браузерное хранилище.

Во время сохранения поля блокируются, кнопка показывает «Сохраняем…»; при ошибке поля остаются заполненными и доступны для повторной попытки. Для заметки используется одна кнопка: нативная в Telegram, обычная в браузере. Браузерные сценарии проверяют отмену выхода, подтверждённый выход без записи в API, переключатели услуги и статуса, отдельное сохранение настроек и прайса и закрытие окон клиента и траты.

### Проверка объёма данных и параллельной работы

`npm run test:load` создаёт отдельную временную SQLite с настоящими миграциями, 10 искусственными мастерами и 10 000 записями. Проверяются 100 одновременных запросов, 20 параллельных сохранений и попытки удаления чужих записей. Сверяются ID и содержимое всех прежних строк; одинаковый клиент при параллельном сохранении создаётся один раз на мастера. В журнал выводятся p50/p95 и максимум времени ответов для этого запуска.

Это проверка настоящих обработчиков Worker с локальной SQLite. Она не измеряет пропускную способность Cloudflare/Turso и не является оценкой предельного числа пользователей в рабочем окружении. Сеть Telegram подменяется; `.dev.vars` и рабочая база не используются. Нагрузочные сценарии также входят в обычный `npm test` и CI.

## 🚀 Быстрый запуск и деплой

Требуется поддерживаемая версия Node.js: 22.12+ в ветке 22, ветка 24 или 26+. Это требование обновлённых Vitest и Wrangler.

### 1. Установка зависимостей
```bash
npm install
```

### 2. Секреты Cloudflare
Задаются через команду `wrangler secret put`:
```bash
npx wrangler secret put BOT_TOKEN        # Токен бота от @BotFather
npx wrangler secret put ALLOWED_IDS      # Telegram ID мастеров через запятую
npx wrangler secret put WEBHOOK_SECRET   # Секретная строка для защиты вебхука
npx wrangler secret put TURSO_AUTH_TOKEN # Токен доступа к базе Turso
```

Переменная `TURSO_DATABASE_URL` указывается в `wrangler.toml` или в `.dev.vars` для локальной разработки.

### 3. Автоматическое применение миграций к Turso
В проект встроен скрипт накатывания недостающих миграций:
```bash
npm run migrate
```
Скрипт проверяет таблицу `schema_migrations` в Turso и выполняет только не применённые файлы:
- `0001_init.sql` — начальная структура записей
- `0002_notify_22.sql` — перевод уведомлений на 22:00
- `0003_schema_hardening.sql` — нормализация схемы и создание `schema_migrations`
- `0004_notify_options.sql` — настройка `notify_new_appt` и таблица `scheduled_deletes`
- `0005_optional_end_time.sql` — опциональный `end_time`
- `0006_clients_and_schedule.sql` — таблица клиентов `clients` и поля графика работы мастера в `users`
- `0007_client_birthdays.sql` — колонка `birthday` (число и месяц) в `clients` и дата утренней отправки в `users`
- `0013_access.sql` — таблица `access` для команд `/adduser`, `/ban`, `/unban`
- `0014_user_names.sql` — имя и @username пользователя для админ-панели

### 4. Тесты и проверка типов
```bash
npm test
npm run typecheck
```

### 5. Деплой приложения
```bash
npm run deploy
```

### 6. Установка Webhook Telegram
```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<WORKER_URL>/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

## 💬 Команды бота

- `/start` / `/menu` — приветствие, обучение и кнопка входа в Mini App.
- `/today` — расписание на сегодня.
- `/tomorrow` — расписание на завтра.
- `/notify` — принудительно сформировать и прислать вечернее расписание.
- `/id` — узнать свой числовой Telegram ID (строгое совпадение команды).

### 🛠 Команды администратора

Доступны только администраторам (`ADMIN_ID` в `wrangler.toml`: один Telegram ID или несколько через запятую). Всем остальным, включая мастеров, бот на эти команды не отвечает. Команды данные не удаляют; записи мастеров админ правит в приложении (см. «Админ-панель» ниже).

| Команда | Что делает |
| --- | --- |
| `/admin` | список команд администратора |
| `/users` | все пользователи в базе: есть ли доступ (✅/⛔), записи, клиенты, последняя запись; ID из `ALLOWED_IDS`, которые ещё не открывали бота |
| `/user ID` | карточка пользователя: доступ, объёмы данных, доход за текущий месяц, настройки напоминаний, рабочих дней и копий |
| `/stats` | сводка по всей базе: пользователи, записи (сегодня, завтра, впереди, добавлено за 7 дней), клиенты, траты |
| `/health` | проверка базы (время ответа, миграции), бота (`getMe`), webhook (очередь и последняя ошибка доставки) и конфигурации; секреты не показываются |
| `/export` | список пользователей и число их записей |
| `/records` | все записи всех мастеров за всё время одним файлом CSV (UTF-8 с BOM, разделитель «;»: открывается в Excel), первый столбец — ID мастера |
| `/records ID` | то же для одного мастера |
| `/export ID` | присылает в чат CSV (для Excel) и полную JSON-копию данных этого пользователя |
| `/backupall` | присылает JSON-копию данных каждого пользователя из базы |
| `/send ID текст` | личное сообщение пользователю «от администратора» (обычный текст, разметка экранируется) |
| `/broadcast текст` | то же самое всем, у кого есть доступ; в конце итог: доставлено, заблокировали бота, не удалось |
| `/adduser ID` | выдать доступ к боту и приложению (пользователю уходит сообщение; если он ещё не писал боту, бот подскажет, что нужен `/start`) |
| `/ban ID` | закрыть доступ. Данные остаются в базе. Администратора заблокировать нельзя |
| `/unban ID` | снять блокировку |

Доступ = (`ALLOWED_IDS` + выданные через `/adduser`) минус заблокированные через `/ban`. Блокировка сильнее и секрета, и `/adduser`. При ошибке чтения таблицы доступа обычный доступ закрывается: список `ALLOWED_IDS` не должен обходить неизвестные блокировки. Доступ администратора проверяется отдельно; данные мастеров при этом не меняются.

Текст для `/send` и `/broadcast` — до 3500 символов.

#### 🛠 Админ-панель в Mini App

У администратора в шапке приложения появляется кнопка 🛠. Она открывает список мастеров (имя, @username, ID, число записей). Выбор мастера включает режим «правка за мастера»: администратор видит обычное расписание этого мастера и может добавлять, менять, переносить и удалять его записи. Сверху показана плашка с именем мастера и кнопка «Выйти».

- Режим работает по заголовку `X-Act-As: <ID мастера>`; личность всегда берётся из подписи Telegram, а права проверяются на сервере (`ADMIN_ID`).
- Доступны **только записи**. Доходы, траты, клиенты, заметки, настройки, прайс, импорт и экспорт мастера в этом режиме закрыты (читать можно только то, что нужно форме записи: дни, свободные окна, подсказки клиентов, цены, настройки).
- Каждое изменение администратором пишется в лог Worker: `admin-act actor=<админ> target=<мастер> <метод> <путь> status=<код>` (смотреть через `npx wrangler tail`).
- Когда админ добавляет запись, мастер получает обычное сообщение бота «Новая запись».
- Имена в списке мастеров подтягиваются, когда сам мастер открывает приложение (миграция `0014_user_names`). Пока мастер не открывал, виден только ID.
- Администратору не нужно быть в `ALLOWED_IDS`: ему открыто приложение и без доступа мастера.

#### 👁 Наблюдатели

ID наблюдателей задаются в `wrangler.toml` переменной `VIEWER_IDS` (через запятую). Наблюдатель только смотрит: ему доступны `/records` (все записи всех мастеров за всё время, файл для Excel) и `/admin` со своим коротким списком. Все остальные команды администратора, включая рассылки и резервные копии, ему недоступны, и бот на них молчит. Наблюдателю не нужно быть в `ALLOWED_IDS`.
