# 💅 Ежедневник мастера маникюра: Telegram Mini App

Telegram Mini App + бот-ассистент для мастера маникюра и педикюра.  
Работает 24/7 в бессерверном облаке **Cloudflare Workers** с базой данных **Turso (libSQL/SQLite)**.

---

## 🌸 Возможности

- **📅 Полоса недели со свайпом (Пн–Вс)**: индикация записей точками и значок 📝 при наличии заметок.
- **✨ Свободные окна дня**: автоматический расчёт и визуальные бейджи свободных окон с учётом графика работы мастера и существующих записей; клик по окну сразу открывает форму записи на это время.
- **💅 Запись клиентов**:
  - Быстрый выбор времени начала приёма.
  - Опциональная длительность (по умолчанию: маникюр 2 ч, педикюр 1.5 ч, «оба» 3.5 ч, «маникюр + пальцы» 3 ч) с возможностью изменить в один клик.
  - Услуги: маникюр / педикюр / оба / маникюр + пальцы. У «маникюр + пальцы» покрытие не выбирается. Старая отдельная услуга «пальцы» в форме больше не предлагается, но прежние записи с ней открываются и считаются в доходах как раньше.
  - Цена записи (необязательная, целое число). Раздел «Доходы» (иконка с графиком в шапке): диаграмма и итоги за неделю, месяц и год, средний чек, сравнение с прошлым периодом. Валюта задаётся константой `CURRENCY` в начале `webapp/app.js`.
  - Траты на материалы: каждая покупка — отдельная запись (дата, название, сумма). На экране «Доходы» переключатель «Доход / Траты», прибыль за период и разбивка «Траты по материалам»; кнопка «Все траты за период» открывает список с правкой и удалением. Траты попадают и в JSON-бэкап.
  - Прайс услуг (Настройки → «Прайс услуг»): цена подставляется в новую запись и при смене услуги; вручную введённую цену не затирает.
  - Еженедельная резервная копия: по воскресеньям в 21:00 бот присылает JSON (записи, клиенты, траты, прайс, заметки, настройки). Включается в Настройках; пропущенная неделя досылается, повторов нет. Кнопка «Резервная копия сейчас» там же. Автоматического импорта из JSON пока нет.
  - CSV «Доходы и траты» за выбранный период (кнопка на экране «Доходы»): доходы и траты построчно, итоги, прибыль и траты по материалам.
  - Статус записи: запланирована / не пришла / отменена. «Не пришла» и «Отменена» освобождают время (не дают конфликтов, не считаются в окнах, календаре и расписании бота) и не входят в доход. Доход считает только состоявшиеся записи (время начала уже прошло), будущие показываются как «Ожидается»; сорванные записи — отдельной строкой.
  - Восстановление из резервной копии (Настройки → «Восстановить из копии (JSON)»): сначала проверка файла и отчёт «что будет восстановлено», затем замена всех данных одной транзакцией (при сбое ничего не меняется). Понимает и старые копии без поля `format`.
  - Услуги и статусы проверяются в коде (`src/lib/services.ts`, `src/lib/status.ts`), а не в БД: новая услуга или статус не требует миграции.

## Тесты

`npm test` запускает всё: расчёты, интеграционные тесты обработчиков и экранов. Интеграционные и экранные тесты работают на настоящей SQLite (временный файл) с боевыми миграциями и настоящим сервером; подменяется только Telegram. Экранные тесты запускают настоящий `webapp/app.js` в jsdom. Тесты не требуют ни Turso, ни сети. CI (`.github/workflows/ci.yml`) гоняет `typecheck` и `test` на каждый пуш.
  - Раздельные покрытия: с покрытием (гель) / без покрытия.
  - Автоматическая проверка интервальных пересечений $[start, end)$ с понятным предупреждением.
  - Автоподстановка клиентов из базы при вводе имени.
- **👥 База клиентов (отдельный раздел)**:
  - Карточки клиентов с поиском.
  - Номер телефона с быстрым звонком и кликабельная ссылка на профиль Telegram.
  - Индивидуальные заметки мастера (аллергия на материалы, предпочтения, особенности).
  - 🎂 **День рождения клиентки**: указание числа и месяца, праздничный бейдж и **автоматическое напоминание от бота в 10:00 утра** (по Кишиневу) в день рождения клиентки со всеми её контактами.
  - История визитов и кнопка быстрой записи.
- **📝 Заметки на каждый день**: сохраняются в приложении и мгновенно дублируются сообщением в Telegram.
- **🔔 Сообщения о записях и заметках**: бот присылает уведомления при создании и автоматически удаляет их из чата через сутки, чтобы не засорять переписку мастера.
- **🌙 Вечерние напоминания**: бот каждый вечер (по умолчанию в 22:00) присылает расписание на завтра со списком клиентов, контактами (телефон / Telegram) и заметкой.
- **⚙️ Настройки графика**: выбор рабочих дней (Пн–Вс), начала и окончания рабочего дня, времени вечернего уведомления.
- **🔒 Надёжность сессии и защита от гонок**:
  - При истечении срока `initData` (24 часа) отображается понятный экран с кнопкой перезагрузки без ложных ошибок 403.
  - Защита от race conditions на фронтенде при быстром переключении дней (`AbortController` + sequential `requestId`).
- **📊 Экспорт в Excel / CSV**: безопасная выгрузка всех записей в таблицу CSV (с сохранением телефонных номеров с `+` и защитой от CSV-инъекций) прямо в чат Telegram.
- **🎨 Дизайн**: мобильный интерфейс, нежная пудрово-розовая палитра, полная поддержка светлой и тёмной тем Telegram.

## 🛠 Стек технологий

- **Бэкенд**: Cloudflare Workers, TypeScript, Hono.
- **База данных**: Turso (libSQL / SQLite) через `@libsql/client/web` (атомарные транзакции `batch`).
- **Фронтенд**: Чистый JavaScript (Vanilla), HTML5, CSS3 без сборщиков и сторонних фреймворков.
- **Telegram WebApp**: BackButton, MainButton, HapticFeedback, showConfirm.
- **Фоновые задачи**: Cloudflare Cron Triggers (`* * * * *`): проверка вечерних уведомлений и автоудаление сервисных сообщений из чата.
- **Тесты**: Vitest (`npm test`): подпись Telegram, валидация, расчёты, вечерние и недельные уведомления, интеграционные тесты обработчиков и миграций на настоящей SQLite, сквозные тесты экранов (см. раздел «Тесты» ниже).

## 🚀 Быстрый запуск и деплой

### 1. Установка зависимостей
```bash
npm install
```

### 2. Секреты Cloudflare
Задаются через команду `wrangler secret put`:
```bash
npx wrangler secret put BOT_TOKEN        # Токен бота от @BotFather
npx wrangler secret put ALLOWED_IDS      # Telegram ID мастеров через запятую
npx wrangler secret put WEBHOOK_SECRET   # Секретная строка для защиты вебхука
npx wrangler secret put TURSO_AUTH_TOKEN # Токен доступа к базе Turso
```

Переменная `TURSO_DATABASE_URL` указывается в `wrangler.toml` или в `.dev.vars` для локальной разработки.

### 3. Автоматическое применение миграций к Turso
В проект встроен скрипт накатывания недостающих миграций:
```bash
npm run migrate
```
Скрипт проверяет таблицу `schema_migrations` в Turso и выполняет только не применённые файлы:
- `0001_init.sql` — начальная структура записей
- `0002_notify_22.sql` — перевод уведомлений на 22:00
- `0003_schema_hardening.sql` — нормализация схемы и создание `schema_migrations`
- `0004_notify_options.sql` — настройка `notify_new_appt` и таблица `scheduled_deletes`
- `0005_optional_end_time.sql` — опциональный `end_time`
- `0006_clients_and_schedule.sql` — таблица клиентов `clients` и поля графика работы мастера в `users`
- `0007_client_birthdays.sql` — колонка `birthday` (число и месяц) в `clients` и дата утренней отправки в `users`

### 4. Тесты и проверка типов
```bash
npm test
npm run typecheck
```

### 5. Деплой приложения
```bash
npm run deploy
```

### 6. Установка Webhook Telegram
```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<WORKER_URL>/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

## 💬 Команды бота

- `/start` / `/menu` — приветствие, обучение и кнопка входа в Mini App.
- `/today` — расписание на сегодня.
- `/tomorrow` — расписание на завтра.
- `/notify` — принудительно сформировать и прислать вечернее расписание.
- `/id` — узнать свой числовой Telegram ID (строгое совпадение команды).

### 🛠 Команды администратора

Доступны только администратору (`ADMIN_ID` в `wrangler.toml`). Всем остальным, включая других мастеров из `ALLOWED_IDS`, бот на эти команды не отвечает. Разрушающих команд (удаление данных, смена доступа) нет намеренно: доступ задаётся секретом `ALLOWED_IDS`.

| Команда | Что делает |
| --- | --- |
| `/admin` | список команд администратора |
| `/users` | все пользователи в базе: есть ли доступ (✅/⛔), записи, клиенты, последняя запись; ID из `ALLOWED_IDS`, которые ещё не открывали бота |
| `/user ID` | карточка пользователя: доступ, объёмы данных, доход за текущий месяц, настройки напоминаний, рабочих дней и копий |
| `/stats` | сводка по всей базе: пользователи, записи (сегодня, завтра, впереди, добавлено за 7 дней), клиенты, траты |
| `/health` | проверка базы (время ответа, миграции), бота (`getMe`), webhook (очередь и последняя ошибка доставки) и конфигурации; секреты не показываются |
| `/export` | список пользователей и число их записей |
| `/records` | все записи всех мастеров за всё время одним файлом CSV (UTF-8 с BOM, разделитель «;»: открывается в Excel), первый столбец — ID мастера |
| `/records ID` | то же для одного мастера |
| `/export ID` | присылает в чат CSV (для Excel) и полную JSON-копию данных этого пользователя |
| `/backupall` | присылает JSON-копию данных каждого пользователя из базы |
| `/send ID текст` | личное сообщение пользователю «от администратора» (обычный текст, разметка экранируется) |
| `/broadcast текст` | то же самое всем из `ALLOWED_IDS`; в конце итог: доставлено, заблокировали бота, не удалось |

Текст для `/send` и `/broadcast` — до 3500 символов.

#### 👁 Наблюдатели

ID наблюдателей задаются в `wrangler.toml` переменной `VIEWER_IDS` (через запятую). Наблюдатель только смотрит: ему доступны `/records` (все записи всех мастеров за всё время, файл для Excel) и `/admin` со своим коротким списком. Все остальные команды администратора, включая рассылки и резервные копии, ему недоступны, и бот на них молчит. Наблюдателю не нужно быть в `ALLOWED_IDS`.
